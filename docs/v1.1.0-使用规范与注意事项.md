## 一、v1.1.0 变更概览

### 1. 相对 1.0.5 的破坏性变更

1. **`clearTags(['a','b'])` 改为交集**  
   仅删除**同时**挂在全部给定标签上的缓存。单标签行为不变。若业务曾依赖「并集清理」，需改为多次 `clearTags('a')` / `clearTags('b')`。

2. **`force_validate` 默认改为 `false`**  
   参数指纹已保证 key 唯一性；过滤只影响哈希输入形态，**不是安全边界**。需要旧行为时在配置里显式打开。

3. **`cluster()` 克隆隔离 `LocalCache`**  
   各绑定实例各自持有独立进程内数组缓存；清理只 flush **当前实例**本地缓存，不再一次清空所有克隆上的本地热点。

### 2. 多 Redis 集群手动切换（自 1.0.5 起）

同一套 Laravel 应用需要访问多地 Redis 集群时，通过 `cluster()` 显式指定本次操作连到哪个集群：

```php
use HwlowellRequestCache\RequestCache;

// 未绑定：走 default_connection
$data = RequestCache::get('users', ['id' => 1]);

// 绑定广州集群读
$data = RequestCache::cluster('gz')->get('users', ['id' => 1]);

// 绑定香港集群写
RequestCache::cluster('hk')->set('users', ['id' => 1], ['name' => '张三'], 600);
```

绑定对以下 API 全部生效：`get`、`set`、`delete`、`mget`、`mset`、`remember`、`warm`、`clearGateway`、`clearAll`、`clearTags`。

相关配置：

```php
// config/request_cache.php
'redis_cluster' => [
    'enabled' => true,
    'hash_tag' => 'request-cache',
    'cluster_safe_mode' => true,
    'scan_strategy' => 'all_nodes',
    'default_connection' => 'default',
    'connections' => [], // 留空自动推导；生产建议显式白名单
],
```

- `default_connection`：未调用 `cluster()` 时，数据读写、当前连接清理、统计与监控使用的权威连接名，默认 `default`。
- `connections`：允许手动切换的连接名白名单，留空表示自动推导。

### 3. v1.1.0 重要修复与新增能力

- Redis / RedisCluster API 经 `RedisClientAdapter` 抹平；Cluster 上不再调用不存在的 `pipeline()`。
- 异常捕获统一为 `\Throwable`；关键路径经 `CacheLogger` 打 warning（有 Laravel Log 时）。
- 新增 `request_cache.enable_logging`（默认 `false`）：关闭时不写任何包内诊断日志；排查时可临时设为 `true`，或 `CacheLogger::setEnabled(true)`。
- 标签索引写入移出 pipeline；遗留 SET 可迁移为 ZSET。多标签 `clearTags` 交集删除后只 `zrem` 被删成员，**不再 `DEL` 整张索引**，避免单标签 key 变孤儿。
- 非 UTF-8 缓存值用 serialize 信封兜底；解码 `unserialize` 使用 `allowed_classes => false`。
- `all_nodes` 节点连接合并 `database.redis.clusters.options`（含 password）。
- `remember()`：`enable_extend` 开启时拉长持锁 TTL，回调前后 `renewLock` 使用**同一拉长 TTL**。
- 只传 `cache` 段构造实例时，会从应用配置补齐 `request_cache` 段，避免 version 等静默丢失。

## 二、使用规范

### 1. 配置分工：节点在 database.php，行为在 request_cache.php

`redis_cluster` 只控制本包的集群兼容行为，**不定义 Redis 节点**。节点列表、认证、连接复用一律配置在宿主项目的 `config/database.php`，由 Laravel Redis Manager 统一管理。本包不提供独立连接池。

```php
// config/database.php
'clusters' => [
    'default' => [
        ['host' => env('REDIS_LOCAL_HOST_1'), 'port' => 6379],
        ['host' => env('REDIS_LOCAL_HOST_2'), 'port' => 6379],
    ],
    'gz' => [
        ['host' => env('REDIS_GZ_HOST_1'), 'port' => 6379],
    ],
    'hk' => [
        ['host' => env('REDIS_HK_HOST_1'), 'port' => 6379],
    ],
],
```

集群带密码时，密码放在 `clusters.options`（Laravel 惯例），不必复制到每个 seed；节点条目上的 password 仍可覆盖：

```php
'clusters' => [
    'options' => [
        'password' => env('REDIS_CLUSTER_PASSWORD'),
    ],
    'hk' => [ /* 节点列表 */ ],
],
```

### 2. `enabled` 不是「仅控制 SCAN」的开关

- `enabled = false`：调用 `cluster()` 抛 `LogicException`；未绑定路径**仍然按 `default_connection` 工作**。
- `enabled = true` + 未调用 `cluster()`：走 `default_connection`，`scan_strategy` 按配置值生效。
- `enabled = true` + 调用 `cluster('x')`：走 `x`，`scan_strategy` 强制降级（见第四节）。

在真正的 Redis Cluster 上不要用 `enabled=false`「关闭多集群」——会同时丢掉 hash tag 与 `cluster_safe_mode`，易触发 `CROSSSLOT`。单集群场景应把 `connections` 收敛为单个连接名。

### 3. 白名单推导规则

`connections` 留空时：

- 顶层：只接收数组型连接，排除 `options`、`client`、`clusters`。
- `database.redis.clusters` 下：只接收数组值，显式排除 `options`。

显式写了非数组配置则抛 `InvalidArgumentException`，**fail-closed**。生产建议显式白名单。

### 4. 锁与统计的连接归属：故意不同

| 能力 | 归属连接 | 原因 |
| --- | --- | --- |
| 分布式锁 | 跟随 `cluster()` 绑定的目标集群 | 锁与数据必须同集群 |
| 统计计数 | 固定写 `default_connection` | 需要单一权威视角；`CacheMonitor` 也读该连接 |

`CacheMonitor` 不支持运行时 `cluster('x')`，默认监控连接遵循 `default_connection`。

### 5. LocalCache：按连接命名空间 + 克隆隔离

- 本地缓存 key 用 `hash('sha256', 有效连接名) . ':' . redisKey` 隔离，避免跨连接串读。
- `cluster()` 返回的克隆通过 `__clone` **新建** `LocalCache` 对象，各绑定实例互不共享进程内热点。
- `clearGateway()` / `clearAll()` / `clearTags()` / `delete()` 等清理只 flush **当前实例**的本地缓存。

### 6. 诊断日志

```php
'request_cache' => [
    'enable_logging' => false, // 生产默认关；排查降级/编码失败时临时打开
],
```

或运行时：`CacheLogger::setEnabled(true)`。

## 三、实例语义：哪些方法返回克隆，哪些直接改当前实例

**`cluster()` 返回克隆实例**，绑定只在这条调用链上生效：

```php
$data = RequestCache::cluster('hk')->get('users', ['id' => 1]);
```

**其余链式方法返回 `$this`，直接修改当前实例**：`tags()`、`version()`、`sizeLimit()`、`encryptData()`、`enableStats()`、`setForceValidate()`。

通过 Facade 调用 `RequestCache::version('2.0')` 会改动容器单例，影响此后同一请求内的所有调用。

```php
// 不推荐：污染容器单例
RequestCache::version('2.0')->get('users', ['id' => 1]);

// 推荐：需要改变实例状态时自建实例
$cache = new RequestCache();
$data = $cache->version('2.0')->get('users', ['id' => 1]);

// cluster() 安全，可直接在 Facade 上链式调用
$data = RequestCache::cluster('hk')->get('users', ['id' => 1]);
```

## 四、注意事项

### 1. 多集群的硬前提

各地集群必须共用同一套 `APP_KEY`、`APP_NAME`、`APP_ENV` 与缓存 `version`，否则跨集群读取必然 miss。跨系统访问不在本能力范围内。

### 2. 本包只提供切换机制，不提供跨集群策略

明确不提供：自动兜底顺序、自动回填、删除广播、跨集群一致性、格式转换、超时/熔断。全部由业务编排。

```php
$params = ['id' => 1];

$data = RequestCache::get('users', $params);

if ($data === null) {
    $data = RequestCache::cluster('gz')->get('users', $params);
}

if ($data === null) {
    $data = RequestCache::cluster('hk')->get('users', $params);
}

if ($data !== null) {
    RequestCache::set('users', $params, $data, 600); // 回填本地
}
```

### 3. `all_nodes` 适用范围很窄

只在**未调用 `cluster()`**、或**绑定名恰好等于 `default_connection`** 时生效。绑定其他集群时运行时强制降级为 `single_connection`（配置值本身不被改写）。

监控结果通过 `scope` 标注：`current_connection`、`cluster_aggregate`、`cluster_partial`。

解析节点时会向宿主 `database.redis` 注入 `request_cache_cluster_node_*` 伪连接名供 SCAN 使用；遍历全部 Redis 连接的宿主监控会看到这些名字。仅在 manager 缺配置时才会 `forgetInstance('redis')`。

### 4. 清理能力边界（最需要警惕）

> **绑定非默认集群后，`clearGateway()` 与 `clearAll()` 只覆盖该集群的第一个 master 节点。**

方法仍可能返回 `true`，其余分片残留靠 TTL 收敛。需要覆盖整个集群时，在未绑定的默认集群上使用 `scan_strategy => 'all_nodes'`。

因此**所有缓存写入都应设置合理 TTL**，不要只依赖清理回收。

`clearAll()` / `clearGateway()` 每删 1000 个 key 会限流休眠；百万级 keyspace **不要在 Web 请求里同步清理**，应放进队列。

### 5. 统计只覆盖 `remember()`

直接 `get()` / `set()` **不计入** hit_rate。混用时命中率会低估。

### 6. 锁续期

同步 PHP 无可靠中途心跳；依赖「拉长 TTL + 回调前后续期」。超长回调请调大 `cache.lock.expire` / `extend_interval`。

### 7. 其余常规约束

- **数据大小**：默认上限 1MB，超限不写入，`set()` 返回失败。
- **参数过滤**：`force_validate` 默认 `false`；开启后清洗有损，但 key 额外带原始参数指纹，不同原始入参不会撞 key。参数顺序始终不影响 key。
- **gateway**：只保留字母数字下划线连字符；`clearGateway()` 与 `generateKey()` 同一套规则。
- **加密**：依赖 Laravel `encrypt` / `decrypt`，非 Laravel 环境自动跳过。
- **`shared_mode=true`**：Redis 写失败返回失败且不写 LocalCache；多实例严格共享必须开启。
- **`cluster_safe_mode`**：真集群建议保持 `true`。
- **监控成本**：`CacheMonitor::getStats()` 等在大 keyspace 上仍可能昂贵，应按需调用，避免高频轮询。
- **RediSearch**：`RediSearchService` 不随包提供；`search()` 等缺失时降级返回空值，不 Fatal。

## 五、四种部署形态的配置

贯穿规则：`redis_cluster.enabled` 同时控制 hash tag、多 key 逐 key 降级、是否允许 `cluster()`。

| 形态 | 后端 | `enabled` | `cluster_safe_mode` | `scan_strategy` | 能否 `cluster()` |
| --- | --- | --- | --- | --- | --- |
| A | 单台 Redis | `false` | 不生效 | `single_connection` | 否 |
| B | 多台独立 Redis | `true` | `false` | `single_connection` | 是 |
| C | 单个 Redis Cluster | `true` | `true` | `all_nodes` | 用白名单禁止 |
| D | 多个 Redis Cluster | `true` | `true` | `all_nodes` | 是 |

### 形态 A：单 Redis 实例

```php
// config/database.php
'redis' => [
    'client' => 'phpredis',
    'default' => [
        'host' => env('REDIS_HOST', '127.0.0.1'),
        'port' => env('REDIS_PORT', 6379),
        'password' => env('REDIS_PASSWORD'),
        'database' => 0,
    ],
],
```

```php
// config/request_cache.php
'cache' => [
    'strategy' => [
        'primary' => 'redis',
        'secondary' => 'array',
        'fallback' => true,
        'shared_mode' => true, // 多台 PHP 共用一台 Redis 时建议开启
    ],
    'redis_cluster' => [
        'enabled' => false,
        'hash_tag' => null,
        'cluster_safe_mode' => false,
        'scan_strategy' => 'single_connection',
        'default_connection' => 'default',
        'connections' => [],
    ],
],
```

### 形态 B：多台独立 Redis，手动切换

**`enabled` 必须为 `true`** 才能 `cluster()`。不要设 `scan_strategy => 'all_nodes'`（会去 `clusters` 里找节点，易静默扫错库）。

```php
'redis' => [
    'client' => 'phpredis',
    'default' => ['host' => env('REDIS_HOST'), 'port' => 6379, 'database' => 0],
    'gz'      => ['host' => env('REDIS_GZ_HOST'), 'port' => 6379, 'database' => 0],
    'hk'      => ['host' => env('REDIS_HK_HOST'), 'port' => 6379, 'database' => 0],
],
```

```php
'redis_cluster' => [
    'enabled' => true,
    'hash_tag' => 'request-cache',
    'cluster_safe_mode' => false,
    'scan_strategy' => 'single_connection',
    'default_connection' => 'default',
    'connections' => ['default', 'gz', 'hk'],
],
```

开启 `enabled` 一定会带 hash tag，单实例上功能无害但会改变 key 字面形态。

### 形态 C：单个 Redis Cluster（关闭多集群切换）

把 `connections` 收敛为单个连接名，不要用 `enabled=false`。

```php
'redis' => [
    'client' => 'phpredis',
    'clusters' => [
        'options' => [
            'password' => env('REDIS_CLUSTER_PASSWORD'),
        ],
        'default' => [
            ['host' => env('REDIS_NODE_1'), 'port' => 6379],
            ['host' => env('REDIS_NODE_2'), 'port' => 6379],
            ['host' => env('REDIS_NODE_3'), 'port' => 6379],
        ],
    ],
],
```

```php
'redis_cluster' => [
    'enabled' => true,
    'hash_tag' => 'request-cache',
    'cluster_safe_mode' => true,
    'scan_strategy' => 'all_nodes',
    'default_connection' => 'default',
    'connections' => ['default'],
],
```

### 形态 D：多个 Redis Cluster，手动切换

```php
'redis_cluster' => [
    'enabled' => true,
    'hash_tag' => 'request-cache',
    'cluster_safe_mode' => true,
    'scan_strategy' => 'all_nodes', // 仅对 default 生效；绑定其他集群时运行时降级
    'default_connection' => 'default',
    'connections' => ['default', 'gz', 'hk'],
],
```

## 六、形态之间切换的迁移影响

改动下列任一项都会**改变 key 字面形态**，旧 key 立即 miss，靠 TTL 回收：

- `redis_cluster.enabled` 在 true/false 间切换
- `hash_tag` / `request_cache.prefix` / `version` 改动

改动 `default_connection` 不改 key 形态，但改变物理落点。

建议低峰切换：先缩短 `default_expire` 让存量收敛，或在**旧配置**下 `clearAll(true)` 后再切新配置。

## 七、场景化使用示例

### 场景 1：接口结果缓存

优先用 `remember()`：自带分布式锁，且会计入命中统计。

```php
use HwlowellRequestCache\RequestCache;

public function detail(int $id)
{
    return RequestCache::remember('user_detail', ['id' => $id], function () use ($id) {
        return User::query()->with('profile')->findOrFail($id)->toArray();
    }, 600);
}
```

### 场景 2：列表页缓存 + 按标签失效

```php
$cache = new RequestCache();

$data = $cache->tags('product', $category)->remember('product_list', [
    'category' => $category,
    'page' => $page,
], fn () => $this->queryProducts($category, $page), 300);

// 单标签：清掉所有挂 product 的缓存
$cache->clearTags('product');

// 多标签：只清「同时」挂 product 与某 category 的缓存（交集）
$cache->clearTags(['product', $category]);
```

标签只对紧随其后的**一次**写入生效，用完即清空；多次写入需每次重新 `tags()`。

若要并集失效（清 A 或清 B），请分别调用：

```php
$cache->clearTags('product');
$cache->clearTags($category);
```

### 场景 3：冷热分离（形态 B）

```php
$user = RequestCache::remember('user', ['id' => $id], fn () => $this->loadUser($id), 600);

$report = RequestCache::cluster('bulk')->remember('report', ['month' => $month], function () use ($month) {
    return $this->buildMonthlyReport($month);
}, 3600);
```

大对象注意 `size_limit`（默认 1MB）：

```php
$cache = new RequestCache();
$cache->sizeLimit(5 * 1024 * 1024);
```

### 场景 4：多地就近读 + 手动回填（形态 D）

见[第四节示例](#2-本包只提供切换机制不提供跨集群策略)。跨地域 RTT 会叠加到接口耗时，建议限制兜底集群数量。

### 场景 5：多地删除

```php
foreach (['default', 'gz', 'hk'] as $name) {
    RequestCache::cluster($name)->delete('users', ['id' => $id]);
}
```

`delete()` 返回值不能区分「key 不存在」与「Redis 不可达」（均为 `false`）。无论 Redis 是否可达，都会先删本实例 LocalCache 对应副本。

### 场景 6：全量清理

```php
// 正确：未绑定 + all_nodes
RequestCache::clearAll(true);

// 错误：绑定后只覆盖第一个 master，仍可能返回 true
RequestCache::cluster('hk')->clearAll(true);
```

### 场景 7：Redis 故障与 shared_mode

```php
$ok = RequestCache::set('users', ['id' => 1], $data, 600);

if (!$ok) {
    // shared_mode=true 且 Redis 不可用时会走到这里
    Log::warning('request cache write failed', ['id' => 1]);
}
```

- `shared_mode=false`：写失败可回落 LocalCache 并返回成功（进程内一致）。
- `shared_mode=true`：写失败返回失败，不写 LocalCache。

Redis 不可达时，`get` / `mget` / `delete` / `remember` / `clearGateway` / `clearTags` / `getStats` 返回安全值，不抛异常穿透。

### 场景 8：整体换版

```php
// 方式一：改配置
'request_cache' => ['version' => '2.0'],

// 方式二：自建实例运行时改版
$cache = new RequestCache();
$data = $cache->version('2.0')->get('users', ['id' => 1]);
```

旧 key 靠 TTL 回收；需立即回收时在换版**之前** `clearAll(true)`。

### 场景 9：实例级覆盖配置

```php
// 只让某个实例走严格共享，不影响容器单例
$strict = new RequestCache([
    'cache' => ['strategy' => ['shared_mode' => true]],
]);

$strict->cacheConfig()->strategy()['shared_mode']; // true
CacheConfig::getStrategy()['shared_mode'];         // 仍是全局值
```

只传 `cache` 段时，`request_cache`（version / prefix / size_limit 等）会从应用配置自动补齐。改全局请用 `RequestCache::loadConfig()`。

## 八、常见配置错误对照

| 现象 | 直接原因 | 处理 |
| --- | --- | --- |
| `Couldn't map cluster keyspace using any provided seed` | 密码写在节点上未进 `clusters.options` | 密码移到 `clusters.options.password` |
| `cluster()` 抛 `LogicException` | `enabled=false` | 置 `true`（独立多 Redis 同样需要） |
| `cluster()` 抛 `InvalidArgumentException` | 不在白名单 | 写入 `connections` |
| `CROSSSLOT ...` | 真集群上 `enabled` 或 `cluster_safe_mode` 为 false | 两项都置 true |
| 清理返回 true 但 key 还在 | 绑定非默认集群只扫首 master；或形态 B 误开 `all_nodes` | 未绑定 + `all_nodes`；形态 B 用 `single_connection` |
| 命中率偏低 | 统计只覆盖 `remember()` | 按口径解读或统一用 `remember()` |
| 换配置后全 miss | 改了 `enabled` / `hash_tag` / `prefix` / `version` | 预期行为，见第六节 |
| Facade 链式后行为异常 | `version()`/`tags()`/`sizeLimit()` 污染单例 | 自建实例，见第三节 |
| 多标签 `clearTags` 清得比预期少 | 1.1.0 起为交集 | 并集请多次单标签清理 |
| 参数清洗「不像以前」 | `force_validate` 默认 false | 需要旧清洗时显式打开 |

## 九、升级检查清单

### 从任意版本到 1.1.0

- [ ] `composer` 版本对齐 `1.1.0`，执行 `vendor:publish`（如需）对齐配置项（含 `enable_logging`、`force_validate` 默认值）
- [ ] 确认是否依赖 `clearTags([...])` **旧并集**语义，必要时改为多次单标签清理
- [ ] 确认 `force_validate` 是否要显式打开
- [ ] Cluster 保持 `cluster_safe_mode=true`（默认）
- [ ] `all_nodes` 场景验证密码仅在 `clusters.options` 时清理/监控仍可用
- [ ] 确认 `default_connection` 在 `database.php` 中真实存在；显式列出 `connections` 白名单
- [ ] 排查 Facade 上的 `version()` / `tags()` / `sizeLimit()` / `encryptData()`，改为自建实例
- [ ] 清理路径避免绑定非默认集群；绑定场景靠 TTL
- [ ] 按第五节核对形态：形态 B 勿开 `all_nodes`；形态 C/D 保持 `cluster_safe_mode`
- [ ] 标签索引 SET→ZSET：升级后首次带标签写入会迁移；强依赖标签失效时可主动 `clearAll(true)`
- [ ] 监控接口勿高频轮询 `getStats()` / `getKeyDistribution()`
- [ ] 回归隔离前缀下的 smoke / deep / audit（见 laravel-lab）

### 从更早版本额外注意

- 缓存 key 算法与信封格式相对早期版本有过变更，升级可能等同一次冷启动；低峰发布并确认回源承受能力。
- `new RequestCache($config)` 不再改写全局静态配置；需改全局时显式 `RequestCache::loadConfig()`。

## 十、相对 1.0.5 的行为变化

### 会改变调用语义

- **`clearTags([...])` 交集**；多标签清理后保留各标签索引中未被交集命中的成员。
- **`force_validate` 默认 `false`**。
- **`cluster()` LocalCache 隔离**：清理不再 flush「所有克隆」上的本地热点，只 flush 当前实例。

### 会改变运行时稳定性（通常向好）

- Cluster 路径经 `RedisClientAdapter`；`mset` 不再误用 `pipeline()`。
- 全量 `\Throwable` 捕获 + 可选 `CacheLogger`。
- 非 UTF-8 值可缓存；`unserialize` 限制 `allowed_classes=false`。
- `enable_extend` 持锁 TTL 拉长且续期不再把 TTL 打回短值。
- `all_nodes` 继承 `clusters.options` 凭据。
- 构造只传 `cache` 段时补齐 `request_cache` 段。

### 仍须业务侧知晓的限制

- 统计仍只覆盖 `remember()`。
- `delete()` 仍不能区分「不存在」与「不可达」。
- 绑定非默认集群的全量清理仍只覆盖 PhpRedis Cluster 第一个 master。
- 本包不提供跨集群自动兜底 / 回填 / 删除广播。
- `RediSearchService` 仍不随包提供。
