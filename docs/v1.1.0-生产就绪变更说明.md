# RequestCache v1.1.0 生产就绪变更说明

本文档说明 v1.1.0（A+Y）相对 1.0.5 的破坏性变更、运维注意与升级要点。基础用法见 [README.md](../README.md)，1.0.5 多集群形态说明见 [v1.0.5-使用规范与注意事项.md](./v1.0.5-使用规范与注意事项.md)。

## 破坏性变更

1. **`clearTags(['a','b'])` 改为交集**  
   仅删除同时挂在全部给定标签上的缓存。单标签行为不变。若业务曾依赖「并集清理」，需改为多次 `clearTags('a')` / `clearTags('b')`。

2. **`force_validate` 默认改为 `false`**  
   参数指纹已保证 key 唯一性；过滤只影响哈希输入形态，不是安全边界。需要旧行为时在配置里显式打开。

3. **`cluster()` 克隆隔离 `LocalCache`**  
   各绑定实例不再共享同一进程内数组缓存对象；清理只 flush 当前实例本地缓存。

## 重要修复

- Redis / RedisCluster API 经 `RedisClientAdapter` 抹平；Cluster 上不再调用不存在的 `pipeline()`。
- 异常捕获统一为 `\Throwable`，关键路径经 `CacheLogger` 打 warning（有 Laravel Log 时）。
- 标签索引写入移出 pipeline；遗留 SET 可迁移为 ZSET。
- 非 UTF-8 缓存值用 serialize 信封兜底，避免永久穿透。
- `all_nodes` 节点连接合并 `database.redis.clusters.options`（含 password）。
- `remember()`：`enable_extend` 开启时拉长持锁 TTL，并在回调前后 `renewLock`。
- 只传 `cache` 段构造时，会从应用配置补齐 `request_cache` 段。

## 运维注意

1. **`all_nodes` 伪连接**  
   解析节点时会向宿主 `database.redis` 注入 `request_cache_cluster_node_*` 连接名，供 SCAN 使用。遍历全部 Redis 连接的宿主监控会看到这些名字。仅在 manager 缺配置时才会 `forgetInstance('redis')` 并打日志。

2. **凭据**  
   密码可放在 `clusters.options`（Laravel 惯例），不必再复制到每个 seed 节点条目；节点条目上的 password 仍可覆盖。

3. **监控成本**  
   `CacheMonitor::getStats()` 在大 keyspace 上仍可能昂贵；已避免双重全量扫描，但仍应按需调用。

4. **锁续期**  
   同步 PHP 无可靠中途心跳；依赖「拉长 TTL + 回调前后续期」。超长回调请自行调大 `cache.lock.expire` / `extend_interval`。
